Scraper — Data Collection & Filtering

The scraper loads active user profiles from DynamoDB, constructs search queries by combining job titles with target locations, and hits the SerpAPI Google Jobs engine. Each result passes through a multi-stage filtering pipeline before being written to the jobs table.

Filtering Pipeline

Deduplication

SHA-256 hash of profile + title + company creates deterministic job IDs. Existing items are skipped via DynamoDB conditional writes.

Keyword Gating

Two-tier keyword system: tier 1 keywords are required (must-have), tier 2 boost relevance. Configurable minimum threshold per profile.

Geographic Enforcement

Hard geographic filter requires job locations to match profile geo_keywords (city names, neighborhoods, "remote"). Prevents results that name a city in the description but are actually located elsewhere.

Apply Link Extraction

Captures apply_options array from SerpAPI — multiple job board links per listing. Stores primary apply_url, apply_source, and all alternatives for multi-source email rendering.

Scorer — Bedrock AI Relevance

Each new listing is sent to Amazon Bedrock (Claude Sonnet) with the user's full profile context. The model returns a structured JSON response with five weighted dimension scores and a natural language reasoning summary.

Prompt Engineering

Few-Shot Examples
Three reference examples (high / medium / low match) give the model calibration anchors for consistent scoring across runs.
Structured Output
JSON schema enforcement with fallback parsing — strips markdown fences and handles malformed responses gracefully.
Profile Injection
Full user profile (keywords, companies, locations, exclusions) is injected as context so scoring is personalized per user.
Throttle & Cost Tracking
5-second delays between API calls prevent rate limiting. Per-run cost tracking logs actual Bedrock spend.

Notifier — Email Delivery

Two notification channels via SNS: a weekly digest for all listings scoring 40+ and individual hot-match alerts for listings scoring 75+. Each email includes the AI reasoning summary, dimension breakdown, and clickable apply links from multiple job boards.

Listings transition through three DynamoDB status states — STATUS#new → STATUS#scored → STATUS#notified — ensuring no listing is processed or emailed twice.

DynamoDB — Single-Table Design

All data lives in one DynamoDB table using a composite primary key (PK + SK) pattern. This eliminates cross-table queries and keeps the architecture simple while supporting multiple entity types.

User Profiles

PK: PROFILE#{name} / SK: CONFIG — Contains search queries, locations, keywords (tier 1 + 2), target companies, exclusions, geographic filters, and notification preferences.

Job Listings

PK: JOB#{hash} / SK: STATUS#{state} — Stores title, company, location, description, apply links, score breakdown, AI reasoning, and timestamps. 90-day TTL auto-expires old data.

GSI: StatusIndex

Global secondary index on status + timestamp enables efficient queries for "all new listings" or "all scored listings" without full table scans.

Conditional Writes

DynamoDB condition expressions prevent duplicate inserts. The scraper attempts a write and silently skips if the job already exists — no race conditions.

Design Decisions

Key architectural tradeoffs and lessons from building and operating the system.

Problem

AI Scoring vs. Keyword Filtering

Strict keyword filtering missed relevant roles that used different terminology. Solution: lower the keyword gate, widen the search aperture, and let Bedrock handle nuanced relevance. The AI catches semantic matches that regex can't.

Problem

Geographic False Positives

Searching "security architect Miami" returned jobs in other states that mentioned Miami in their description. Solution: hard filter on the job location field itself, requiring explicit city names or "remote" indicators.

Problem

Apply Link Fragmentation

Listings appear on multiple boards with different apply URLs. Solution: extract the full apply_options array, store all sources, and render primary + alternatives in notifications so users can pick their preferred board.

Problem

Cost Control at Scale

Bedrock calls could get expensive with hundreds of listings. Solution: filter aggressively before scoring (dedup → keywords → geography), throttle API calls, and track per-run costs. Current: ~$0.003/listing.

Tech Stack

Infrastructure as Code

AWS SAM template.yaml defines all resources — Lambda, DynamoDB, SNS, EventBridge, IAM, and Secrets Manager references. Single sam deploy for the full stack.

Compute

Three Python 3.12 Lambda functions with 256MB memory and 5-minute timeouts. Each function has single-purpose scope with least-privilege IAM roles.

Storage

DynamoDB on-demand capacity, single-table design with GSI for status queries, TTL for automatic 90-day expiry, and conditional writes for idempotency.

AI / ML

Amazon Bedrock invoking Claude Sonnet with structured JSON prompts, few-shot calibration examples, and per-profile context injection. Fallback parsing for malformed responses.

Notifications

Two SNS topics — digest (weekly, score ≥ 40) and alerts (immediate, score ≥ 75). HTML emails with score breakdowns and clickable multi-source apply links.

External Data

SerpAPI Google Jobs engine provides structured job data including titles, companies, locations, descriptions, and apply_options. API key stored in Secrets Manager.
