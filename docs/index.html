Overview

Built to solve a real problem: monitoring dozens of job boards for highly specific GenAI security roles in financial services across Florida's growing "Wall Street South" corridor — from Brickell and Coconut Grove up through the Space Coast to Cape Canaveral. Rather than manually searching weekly, this agent runs autonomously every Monday — scraping listings, filtering by keyword relevance, scoring with AI, and delivering a prioritized digest with clickable apply links.

The system supports multiple user profiles with independent search criteria, keyword tiers, geographic preferences, and target company lists. Each profile gets personalized AI scoring and notifications. A self-service profile builder web app is in development to enable family members with completely different career fields to create their own agent configurations.

AI-Powered Scoring

5-Dimension Weighted Scoring with Bedrock

Each job listing is scored by Amazon Bedrock (Claude Sonnet) across five weighted dimensions. The prompt uses few-shot examples showing high, medium, and low match scenarios to calibrate scoring consistency. Bedrock returns structured JSON with per-dimension scores and a reasoning summary.

Few-Shot Examples

Three calibration examples (high/medium/low match) in the system prompt ensure consistent scoring across varied job descriptions and reduce hallucinated scores.

Structured JSON Output

Bedrock returns per-dimension scores, a weighted total, and a reasoning string. JSON cleanup handles markdown fences that models occasionally wrap around output.

Cost-Controlled

Pre-filtering eliminates ~65% of listings before they reach Bedrock. 5-second throttle between API calls. Actual cost: ~$0.003 per listing scored.

Tech Stack

Compute

Three AWS Lambda functions (Python 3.12) orchestrated by EventBridge with staggered cron schedules. Deployed via SAM/CloudFormation with infrastructure as code.

Data

DynamoDB single-table design with GSI for status-based queries. TTL for automatic 90-day cleanup. PAY_PER_REQUEST billing. Stores profiles, listings, scores, and apply URLs.

Security

API keys in Secrets Manager. IAM least-privilege per Lambda. DynamoDB encryption at rest. No secrets in environment variables. Structured JSON logging throughout.

AI / ML

Amazon Bedrock with Claude Sonnet for 5-dimension job scoring. Few-shot prompt engineering with structured JSON output. Cost-capped with pre-filtering and throttling.

Notifications

Dual SNS topics: weekly digest (score ≥ 40) and instant hot alerts (score ≥ 75). Emails include score breakdowns, AI reasoning, and clickable apply links from multiple job boards.

Scraper Intelligence

Captures apply_options array from SerpAPI with direct links to Indeed, LinkedIn, Dice, and other boards. Hard geographic filtering with 30+ Florida location keywords.

DynamoDB Design

Single-Table, Multiple Entity Types

Profiles, job listings, scores, and configuration all live in one table — differentiated by key structure following DynamoDB best practices. This eliminates cross-table joins and simplifies IAM permissions.

Primary Keys

PK: SOURCE#google_jobs | PROFILE#chris
SK: JOB#abc123 | CONFIG
Enables direct lookups and source-based queries.

GSI1 — Status Index

GSI1PK: STATUS#new | STATUS#scored
GSI1SK: DATE#2026-02-15
Powers the scorer Lambda: "get all new listings, newest first."

Security Decisions

🔐
Secrets Manager over environment variables. API keys are retrieved at runtime via boto3, never stored in Lambda configuration. Supports rotation without redeployment.
🛡️
Least-privilege IAM. Each Lambda gets its own role scoped to only the resources it needs. Scraper can read/write DynamoDB and read Secrets Manager — nothing else.
🔒
DynamoDB encryption at rest. AWS-managed keys (SSE-S3) enabled by default. All data encrypted transparently.
🧹
TTL-based data lifecycle. Job listings auto-expire after 90 days. No manual cleanup needed, no stale data accumulation.
📋
Structured JSON logging. All Lambda output uses JSON format for CloudWatch integration. Enables metric filters and correlation across the pipeline.
🌍
Hard geographic filtering. Listings must contain Florida location keywords or remote indicators. Prevents irrelevant results from leaking through despite geographic search parameters.

Intelligent Filtering

Two-Tier Keyword Scoring + Geographic Gate

Before listings reach Bedrock (which costs money per call), a pre-filter scores them based on keyword relevance. This reduces Bedrock API costs by 60-70%. A key design lesson: relying on AI scoring with a broader aperture produces better results than aggressive keyword filtering.

Tier 1 — Must Match (10pts each)

Core role keywords: architect, security, genai, cyber, engineer, bedrock. Must match ≥1 or listing is discarded. Threshold lowered from 2→1 to let Bedrock handle nuanced relevance.

Tier 2 — Boost (5pts each)

Industry and seniority signals: financial services, banking, principal, cloud security, aws, machine learning. Increases score but not required.

Geographic Gate (Hard Filter)

30+ location keywords covering Cape Canaveral to Miami corridor, including Brickell, Coconut Grove, West Palm Beach, Space Coast, and Remote/Hybrid.
